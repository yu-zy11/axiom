# AxiomKernel 发布与回滚手册

> 状态：已接受
> 责任域：Project
> 维护者：发布负责人
> 最后核验：2026-09-18
> 核验依据：构建配置、质量门禁与发布说明模板

## 1. 适用范围

本手册定义版本候选、验证、发布和回滚的最小闭环。当前仓库未规定具体制品仓库或签名平台，因此相关步骤标记为“由发布环境实现”，不得伪造已上传或已签名状态。

## 2. 发布输入

- 明确版本号、目标平台/编译器和支持范围。
- 路线图里程碑已达到退出标准，需求追踪矩阵状态有证据。
- S0/S1 为零；获准遗留的 S2/S3 写入已知问题。
- Public API、错误码、格式兼容变化已审查并有迁移说明。
- 发布说明按模板完成，依赖许可证和数据集来源已复核。

## 3. 候选版本构建与验证

在干净工作树和全新构建目录中执行：

```bash
cmake -S . -B build-release \
  -DCMAKE_BUILD_TYPE=Release \
  -DAXM_ENABLE_TESTS=ON \
  -DAXM_ENABLE_EXAMPLES=ON \
  -DAXM_ENABLE_BENCHMARKS=ON \
  -DAXM_ENABLE_DIAGNOSTICS=ON \
  -DAXM_ENABLE_STRICT_WARNINGS=ON
cmake --build build-release --parallel
ctest --test-dir build-release --output-on-failure
```

同时记录 commit、工具链、平台、CMake 参数、测试结果、性能环境和制品校验和。IO 发布必须保存受支持格式/选项矩阵及 round-trip 结果；插件发布必须记录 API 版本与宿主策略。

## 4. 发布步骤

1. 冻结候选 commit，确认工作树和依赖来源。
2. 生成版本化制品、头文件包、许可证清单及校验和。
3. 在至少一个干净消费者工程中链接 `axiom_kernel` 并运行基本工作流。
4. 发布制品到约定仓库（由发布环境实现），创建不可变版本标签。
5. 发布说明列出新增、修复、接口/诊断/格式变化、已知问题和升级方式。
6. 保存测试报告、性能结果和诊断样例，更新当前进度与需求追踪矩阵。

## 5. 发布后冒烟

- 安装/消费公开头文件，不依赖 `src/axiom/internal/`。
- 运行 `axiom_basic_workflow`。
- 验证结构化失败包含稳定错误码，关键路径可导出诊断。
- 对声明支持的 IO 子集执行导入 → 验证 → 导出 → 再导入。
- 核对版本信息、插件 API 版本和制品校验和。

## 6. 回滚触发与步骤

以下情况触发停止发布或回滚：数据损坏/静默错误、事务污染、核心链路不可用、制品错误、兼容性声明错误或无法解释的重大性能回退。

1. 暂停分发并记录受影响版本、平台、模型/输入和诊断 ID。
2. 将下载/依赖入口恢复到上一已验证版本；已发布的不可变制品不覆盖，只标记撤回。
3. 用最小复现确认旧版本不受影响，并通知集成方回退方式。
4. 按缺陷流程定级；S0/S1 必须增加回归案例后才能重发。
5. 新候选重新完成全部门禁，不在原标签上替换二进制。
